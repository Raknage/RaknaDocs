## 🛠️ Part 1: Hardware Repurposing & OS Installation

### 1. Hardware Preparation & BIOS Configuration

Before installing Ubuntu Server, configure your BIOS/UEFI firmware settings to ensure the server remains accessible without human intervention:

- **Restore AC Power Loss:** Set **Restore on AC Power Loss** to `Power On` or `Last State` so the machine automatically reboots after power outages.
- **Disable C-States / Deep Sleep (Optional):** If repurposing legacy laptop hardware, disable CPU aggressive C-states to prevent sleep states from dropping network connections.
- **Thermal Maintenance:** Clean dust filters and replace thermal paste on legacy hardware.

### 2. Disk Storage & Partitioning Layout (BTRFS)

<Tabs>
  <TabItem label="Single 240 GB SSD Setup (BTRFS)">
    For a modern, resilient home server running on a single 240 GB SSD drive, **BTRFS** is the recommended filesystem. BTRFS uses **subvolumes** sharing a single storage pool, enabling instant Copy-on-Write (CoW) system snapshots, dynamic disk space allocation, and transparent `zstd` compression:

    ```bash
    /                           → BTRFS Root Pool (240 GB SSD)
    ├── subvol=@                → Mounted at / (OS root, packages, configuration)
    ├── subvol=@home            → Mounted at /home (User projects, repositories, developer configs)
    ├── subvol=@docker          → Mounted at /var/lib/docker (Docker layer caches & runtime containers)
    ├── subvol=@data            → Mounted at /var/data (Persistent database volumes & app storage)
    └── subvol=@log             → Mounted at /var/log (System logs & journalctl)
    ```

    <Aside type="tip" title="Finding Drive UUIDs & Configuring /etc/fstab">
      BTRFS supports transparent background file compression (`compress=zstd:1`), which reduces disk space usage by 20–40% while extending SSD lifespan by reducing total disk write cycles.

      #### Step 1: Find your partition's UUID
      Run either `sudo blkid` or `lsblk -f` in your terminal to inspect block device UUIDs:

      ```bash
      # Display filesystem types and UUIDs for all partitions
      sudo blkid

      # Alternatively, view a tree list of disks and UUIDs
      lsblk -f
      ```

      *Example `blkid` output:*
      `/dev/sda3: UUID="3a2b1c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d" TYPE="btrfs"`

      > 💡 **BTRFS Subvolume Rule:** All subvolumes (`@`, `@home`, `@data`, `@log`) on the same physical partition share the **exact same UUID**. You differentiate subv      #### Step 2: Create Target Mount Directories & BTRFS Subvolumes
      Linux requires target mount directories to exist on disk. Create any missing mount points:

      ```bash
      # Create target mount point directories
      sudo mkdir -p /srv/www /srv/docker /srv/postgres /.snapshots
      ```

      > ⚠️ **Subvolume Existence Error (`No such file or directory`):** If `sudo mount -a` reports `mount() failed: No such file or directory`, the subvolume does not exist inside your BTRFS pool yet. Mount the top-level pool (`subvolid=5`) and create missing subvolumes:
      > ```bash
      > # Mount top-level BTRFS pool to /mnt
      > sudo mount -o subvolid=5 /dev/sda3 /mnt   # Replace /dev/sda3 with your BTRFS partition
      >
      > # Create missing subvolumes
      > sudo btrfs subvolume create /mnt/@home
      > sudo btrfs subvolume create /mnt/@www
      > sudo btrfs subvolume create /mnt/@docker
      > sudo btrfs subvolume create /mnt/@postgres
      > sudo btrfs subvolume create /mnt/@snapshots
      >
      > # Unmount top-level pool
      > sudo umount /mnt
      > ```

      #### Step 3: Edit `/etc/fstab`
      Open `/etc/fstab` in `nano`:

      ```bash
      sudo nano /etc/fstab
      ```

      Add or update entries using your real UUID copied from `sudo blkid`:

      ```ini
      # /etc/fstab BTRFS mount entries
      #              <file system>               <mount point>  <type>  <options>                                <dump><pass>
      UUID=68aeee9a-fe50-4bb0-b4ee-93dd17b8295b  /              btrfs  defaults,noatime,compress=zstd:3,subvol=@          0 0
      UUID=68aeee9a-fe50-4bb0-b4ee-93dd17b8295b  /home          btrfs  defaults,noatime,compress=zstd:3,subvol=@home      0 0
      UUID=68aeee9a-fe50-4bb0-b4ee-93dd17b8295b  /srv/www       btrfs  defaults,noatime,compress=zstd:3,subvol=@www       0 0
      UUID=68aeee9a-fe50-4bb0-b4ee-93dd17b8295b  /srv/docker    btrfs  defaults,noatime,compress=zstd:3,subvol=@docker    0 0
      UUID=68aeee9a-fe50-4bb0-b4ee-93dd17b8295b  /srv/postgres  btrfs  defaults,noatime,compress=zstd:3,subvol=@postgres  0 0
      UUID=68aeee9a-fe50-4bb0-b4ee-93dd17b8295b  /.snapshots    btrfs  defaults,noatime,compress=zstd:3,subvol=@snapshots 0 0
      ```

      #### Step 4: Verify `/etc/fstab` syntax before rebooting
      To ensure there are no typos in `/etc/fstab` that could prevent your server from booting:

      ```bash
      # Reload systemd daemon and test all fstab mount entries
      sudo systemctl daemon-reload
      sudo mount -a
      ```

### 3. Ubuntu Server Installation & Partitioning Guidelines

Download the official **Ubuntu Server LTS ISO** (e.g. 24.04 / 26.04) and flash to a USB drive using Rufus or BalenaEtcher.

<Aside type="note" title="Minimal vs Standard Server">
  Neither standard nor minimal Ubuntu Server installs a graphical desktop GUI (unlike Ubuntu
  Desktop). Selecting **Ubuntu Server (Minimal)** strips out ~200+ non-essential CLI tools, Snap
  packages, LXD containers, and background telemetry daemons, creating a lean ~1.5 GB installation
  footprint (vs ~3.5 GB for standard server).
</Aside>

<Aside type="note" title="Swap Partition vs Swap File">
  <Badge text="Recommendation" variant="success" /> Do <strong>NOT</strong> create a dedicated swap
  partition during installation. Modern Ubuntu Server automatically provisions a dynamic{" "}
  <strong>swap file</strong> (<code>/swap.img</code>) on your main SSD partition. Using a swap file
  keeps partitioning simple and allows you to resize swap later (e.g.{" "}
  <code>fallocate -l 4G /swapfile</code>) without needing disk repartitioning.
</Aside>

<Steps>

1. Boot from the installer USB and select **Ubuntu Server (Minimal)** for a clean, lightweight server baseline.
2. On the Guided Storage screen, select **Custom Storage Layout** (or guided disk layout), format the primary system partition as **Btrfs**, and create your desired subvolumes (`@`, `@home`, `@data`).
3. Select **OpenSSH Server** when prompted during the installer package step.
4. Complete the installation, remove USB installation media, and reboot into your fresh server terminal.
5. **Initial System Update & Essential Tools:** Log in and run an immediate system package refresh and install essential CLI editing tools (`nano`, `curl`, `git`, `btop`):

   ```bash
   # Refresh package index and apply latest security upgrades
   sudo apt update && sudo apt upgrade -y
   ```

</Steps>

# Install essential editing, retrieval, and monitoring packages

```bash
   sudo apt install -y nano curl git btop btrfs-progs tmux
```

| Action / Purpose               | Command                     | Notes                                                                 |
| :----------------------------- | :-------------------------- | :-------------------------------------------------------------------- |
| **Refresh Package Index**      | `sudo apt update`           | Fetches latest available package lists from Ubuntu mirrors            |
| **Upgrade Installed Packages** | `sudo apt upgrade -y`       | Installs latest security patches and updates for installed software   |

| **Clean Orphaned Packages**    | `sudo apt autoremove -y`    | Removes leftover dependency packages to reclaim disk space            |

## 🔐 Part 2: Security & Remote Access

### 1. Static LAN IP Reservation (Netplan)

Assign a static IP address to your server so SSH and internal routing targets remain constant across router reboots.

Inspect your network interface name:

```bash
ip link show
# Example output interface: enp2s0
```

Edit your Netplan configuration file at `/etc/netplan/00-installer-config.yaml`:

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp2s0:
      dhcp4: no
      addresses:
        - 192.168.1.xxx/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [1.1.1.1, 8.8.8.8]
      match:
        macaddress: "xx:xx:xx:xx:xx:xx"
      wakeonlan: true
```

Apply the netplan configuration:

```bash
sudo netplan apply
```

### 2. SSH Key Authentication & Hardening

Password-based SSH authentication is vulnerable to brute-force attacks. Secure remote access with `ed25519` SSH key pairs.

<Aside type="tip" icon="open-book">
  More detailed info in [SSH reference](/reference/ssh)
</Aside>

#### Step A: Generate & Transfer SSH Key from Client Machine

On your client machine (laptop/desktop):

```bash
# Generate key pair
ssh-keygen -t ed25519 -C "admin@homeserver.com"

# Copy key to remote server
ssh-copy-id toni@192.168.1.xxx
```

#### Step B: Disable Password Authentication & Root Login

Log into the server and harden `/etc/ssh/sshd_config.d/hardened.conf`:

```ini
PasswordAuthentication no
PubkeyAuthentication yes
PermitRootLogin no
X11Forwarding no
```

Restart the SSH daemon:

```bash
sudo systemctl restart ssh
```

#### Step C: Remote File Transfers (`scp` & `rsync`)

Transfer files securely between your workstation and home server:

```bash
# Local to Remote using scp
scp -r ./my-app toni@192.168.1.xxx:/home/toni/

# Remote log sync using rsync
rsync -avz toni@192.168.1.xxx:/var/log/syslog ./server-syslog.log
```

### 3. Wake-on-LAN (WoL) Setup

Wake-on-LAN allows you to power on your home server remotely over the LAN using a magic ethernet packet.

Verify interface WoL capability:

```bash
sudo ethtool enp2s0 | grep Wake
# Look for: Supports Wake-on: pumbg / Wake-on: g
```

Enable WoL using `ethtool`:

```bash
sudo ethtool -s enp2s0 wol g
```

To wake your home server from another LAN machine or router:

```bash
# Install wakeonlan utility
sudo apt install wakeonlan

# Broadcast magic packet using server MAC address
wakeonlan xx:xx:xx:xx:xx:xx
```

### 4. Firewall (UFW) Configuration & Essential Commands

Configure Uncomplicated Firewall (UFW) to enforce default-deny incoming rules for network security:

<Aside type="note" title="Why Open Ports 80 (HTTP) & 443 (HTTPS)?">
  - **Port 80 (HTTP):** Required for initial HTTP web requests, automatic HTTP-to-HTTPS redirects,
  and automated Let's Encrypt / Caddy ACME HTTP-01 domain validation challenges when issuing SSL
  certificates. - **Port 443 (HTTPS):** Required for secure, encrypted SSL/TLS web traffic to your
  reverse proxies (Caddy/Nginx), web apps, and APIs.
</Aside>

```bash
# Set default policies (block incoming, allow outgoing)
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Allow essential service ports
sudo ufw allow 22/tcp comment 'SSH'
sudo ufw allow 80/tcp comment 'HTTP'
sudo ufw allow 443/tcp comment 'HTTPS'

# Enable firewall
sudo ufw enable
```

#### 🛠️ Essential UFW Command Reference

| Action / Purpose              | Command                                             | Notes                                                    |
| :---------------------------- | :-------------------------------------------------- | :------------------------------------------------------- |
| **Check Status & Rules**      | `sudo ufw status verbose`                           | Shows active status and enabled port rules               |
| **Numbered Rule List**        | `sudo ufw status numbered`                          | Displays rule index numbers needed for deletion          |
| **Delete Rule by Number**     | `sudo ufw delete 3`                                 | Deletes rule #3 from the numbered list                   |
| **Delete Rule by Service**    | `sudo ufw delete allow 80/tcp`                      | Deletes specific port rule                               |
| **Restrict SSH to Local LAN** | `sudo ufw allow from 192.168.1.0/24 to any port 22` | Restricts SSH access strictly to internal LAN subnet     |
| **Allow Custom App Port**     | `sudo ufw allow 3000/tcp comment 'Astro App'`       | Opens port 3000 with a descriptive label                 |
| **Reload Firewall**           | `sudo ufw reload`                                   | Re-applies rule changes without dropping active sessions |
| **Reset Firewall**            | `sudo ufw reset`                                    | Disables UFW and clears all custom rules to defaults     |

<Aside type="caution" title="Troubleshooting Cockpit: 'Cannot refresh cache whilst offline'">
  <p><Badge text="Gotcha" variant="danger" /> Cockpit Software Updates tab reports: <em>Loading available updates failed — Cannot refresh cache whilst offline</em>.</p>

**Cause:** Ubuntu Server uses Netplan with `systemd-networkd` by default. PackageKit queries NetworkManager over D-Bus to check if the network is active. Because NetworkManager is not managing the interface, PackageKit falsely assumes the server is offline and refuses to check updates.

**Fix:** Configure PackageKit to disable the NetworkManager online check in `/etc/PackageKit/PackageKit.conf`:

```bash
# 1. Disable NetworkManager online check in PackageKit config
sudo sed -i 's/UseNetworkManager=true/UseNetworkManager=false/g' /etc/PackageKit/PackageKit.conf

# 2. Restart PackageKit daemon
sudo systemctl restart packagekit
```

Reload the Cockpit web page in your browser.

</Aside>
