## 🌐 Choose Your Ingress Technology

<Tabs>
  <TabItem label="Option A: Cloudflare DNS + Caddy">

    ### Cloudflare API & Caddy Auto-HTTPS

    Combining **Cloudflare DNS** with **Caddy Server** enables automatic HTTPS via Let's Encrypt / ZeroSSL without opening port 80 to the public internet (using Cloudflare DNS-01 ACME challenge).

    #### 1. Cloudflare API Token Setup

    <Steps>
    1. Log in to [Cloudflare Dashboard](https://dash.cloudflare.com/) → **My Profile** → **API Tokens**.
    2. Click **Create Token** → Select template **Edit zone DNS**.
    3. Under **Zone Resources**, select `Include` → `All zones` (or your specific domain).
    4. Copy the generated API Token (e.g. `cf_api_token_abc123...`).
    </Steps>

    #### 2. Installing Caddy with Cloudflare DNS Plugin

    Use `xcaddy` or the official Caddy repository to install Caddy with the Cloudflare DNS module:

    ```bash
    # Install xcaddy
    sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
    curl -1sLf 'https://dl.cloudsmith.io/public/caddy/xcaddy/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-xcaddy-archive-keyring.gpg
    curl -1sLf 'https://dl.cloudsmith.io/public/caddy/xcaddy/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-xcaddy.list
    sudo apt update && sudo apt install xcaddy

    # Build Caddy with Cloudflare DNS plugin
    xcaddy build --with github.com/caddy-dns/cloudflare
    sudo mv caddy /usr/bin/caddy
    ```

    #### 3. Configuring `/etc/caddy/Caddyfile`

    ```caddy
    {
        email admin@example.com
    }

    # Internal Web Service Reverse Proxy
    app.example.com {
        tls {
            dns cloudflare {$CLOUDFLARE_API_TOKEN}
        }
        reverse_proxy localhost:3000
    }

    # Containerized Service Reverse Proxy
    cms.example.com {
        tls {
            dns cloudflare {$CLOUDFLARE_API_TOKEN}
        }
        reverse_proxy localhost:8080
    }
    ```

    Create `/etc/caddy/env` for your API token:
    ```env
    CLOUDFLARE_API_TOKEN=cf_api_token_abc123...
    ```

    Update Caddy systemd service `/lib/systemd/system/caddy.service` to include:
    ```ini
    EnvironmentFile=/etc/caddy/env
    ```

    Start Caddy:
    ```bash
    sudo systemctl daemon-reload
    sudo systemctl enable --now caddy
    ```

  <TabItem label="Option B: Nginx Reverse Proxy">

    ### Nginx + Certbot Setup

    Traditional Nginx setup for port forwarding (ports 80 and 443).

    #### 1. Installation

    ```bash
    sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx
    ```

    #### 2. Nginx Server Block (`/etc/nginx/sites-available/app.example.com`)

    ```nginx
    server {
        listen 80;
        server_name app.example.com;

        location / {
            proxy_pass http://127.0.0.1:3000;
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection 'upgrade';
            proxy_set_header Host $host;
            proxy_cache_bypass $http_upgrade;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }
    ```

    Enable site and request SSL cert:
    ```bash
    sudo ln -s /etc/nginx/sites-available/app.example.com /etc/nginx/sites-enabled/
    sudo nginx -t
    sudo systemctl reload nginx
    sudo certbot --nginx -d app.example.com
    ```

## 🛠 Troubleshooting Ingress Issues

### Cloudflare API Authentication Error (Code: 6003 / Invalid Header)

- **Cause:** Using Global API Key format instead of Scoped API Token, or missing `Bearer` header.
- **Fix:** Ensure you created an **API Token** with `Zone:DNS:Edit` permissions, and test authentication via curl:
  ```bash
  curl -X GET "https://api.cloudflare.com/client/v4/user/tokens/verify" \
       -H "Authorization: Bearer YOUR_CLOUDFLARE_API_TOKEN" \
       -H "Content-Type: application/json"
  ```
