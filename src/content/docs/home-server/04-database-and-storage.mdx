## 🌟 Recommended Default Track: Containerized Database via Docker Volumes

Running database engines inside Docker containers with host-bound volume mounts provides simple upgrading, clean isolation, and zero host pollution.

### 1. PostgreSQL Container with Host Volume Mount

<Aside type="caution" title="BTRFS Copy-on-Write (CoW) & Database Storage Performance">
  <p><Badge text="Critical Performance Gotcha" variant="danger" /> Default BTRFS Copy-on-Write (CoW) causes severe database file fragmentation and write latency!</p>

Because database engines (PostgreSQL, MariaDB, SQLite) perform heavy random 8KB page writes to data files, BTRFS Copy-on-Write forces modified blocks to be written to new locations on disk. Over time, this leads to **extreme disk fragmentation** and write performance degradation.

**The Solution (NOCOW / `chattr +C`):**
Disable Copy-on-Write (`NOCOW`) on your database storage directories **BEFORE** creating database files or launching database containers.

```bash
# 1. Create empty host database directory
sudo mkdir -p /var/data/postgres

# 2. Disable Copy-on-Write (+C flag) BEFORE populating files
sudo chattr +C /var/data/postgres

# 3. Verify NOCOW attribute (+C is active)
lsattr -d /var/data/postgres
# Expected output: ---------------C------ /var/data/postgres
```

> ⚠️ _Important ([Arch Wiki Btrfs Guide](<https://wiki.archlinux.org/title/Btrfs#Copy-on-Write_(CoW)>)): `chattr +C` ONLY takes effect when executed on an **EMPTY directory** BEFORE files are created. Setting `chattr +C` on an existing folder with files does NOT disable CoW for those existing files.\_

</Aside>

Create your persistent NOCOW database directory and start PostgreSQL 16 container:

```bash
sudo mkdir -p /var/data/postgres
sudo chattr +C /var/data/postgres
sudo chown -R $USER:$USER /var/data/postgres

docker run -d \
  --name postgres-db \
  --restart always \
  -e POSTGRES_USER=appuser \
  -e POSTGRES_PASSWORD=securepassword \
  -e POSTGRES_DB=appdb \
  -v /var/data/postgres:/var/lib/postgresql/data \
  -p 5432:5432 \
  postgres:16-alpine
```

### 2. MariaDB / MySQL Container

```bash
sudo mkdir -p /var/data/mariadb
sudo chattr +C /var/data/mariadb
sudo chown -R $USER:$USER /var/data/mariadb

docker run -d \
  --name mariadb-db \
  --restart always \
  -e MYSQL_ROOT_PASSWORD=rootpassword \
  -e MYSQL_DATABASE=wordpress \
  -e MYSQL_USER=wpuser \
  -e MYSQL_PASSWORD=wppassword \
  -v /var/data/mariadb:/var/lib/mysql \
  -p 3306:3306 \
  mariadb:11
```

## 🖥️ Alternative Branch: Bare-Metal Database Services

If you prefer installing database servers directly on the Ubuntu host OS for raw performance without container overhead:

### 1. Install Bare-Metal PostgreSQL

```bash
sudo apt update
sudo apt install postgresql postgresql-contrib
```

### 2. Configure Access Rules & Networking (`pg_hba.conf`)

By default, PostgreSQL listens only on `127.0.0.1`.

To allow local Docker containers or internal LAN machines to connect, edit `/etc/postgresql/16/main/postgresql.conf`:

```ini
listen_addresses = '*'
```

Configure authentication rules in `/etc/postgresql/16/main/pg_hba.conf`:

```ini
# TYPE  DATABASE        USER            ADDRESS                 METHOD
host    appdb           appuser         192.168.1.0/24          scram-sha-256
```

Restart PostgreSQL:

```bash
sudo systemctl restart postgresql
```

## 💾 Automated Database Backups (CRON)

Never rely on container volume snapshots alone. Schedule automated SQL dump backups to a separate backup directory.

### 1. PostgreSQL Automated Backup Script (`backup-postgres.sh`)

Create `/home/toni/scripts/backup-postgres.sh`:

```bash
#!/bin/bash
BACKUP_DIR="/home/toni/backups/postgres"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
mkdir -p "$BACKUP_DIR"

# Execute pg_dump inside container
docker exec postgres-db pg_dump -U appuser appdb > "$BACKUP_DIR/appdb_$TIMESTAMP.sql"

# Compress backup
gzip "$BACKUP_DIR/appdb_$TIMESTAMP.sql"

# Delete backups older than 14 days
find "$BACKUP_DIR" -type f -name "*.sql.gz" -mtime +14 -delete
```

Make executable:

```bash
chmod +x /home/toni/scripts/backup-postgres.sh
```

### 2. Schedule via CRON

Edit crontab:

```bash
crontab -e
```

Add daily 2:00 AM backup entry:

```cron
0 2 * * * /home/toni/scripts/backup-postgres.sh > /dev/null 2>&1
```
