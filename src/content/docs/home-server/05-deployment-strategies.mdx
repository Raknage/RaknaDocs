## 🌟 Recommended Default Track: Docker Compose Multi-Container Stacks

Docker Compose orchestrates multi-container web stacks (such as Astro frontend + Node API + MariaDB) with isolated networking and restart policies.

### 1. Multi-Container Stack (`docker-compose.yml`)

Create a `docker-compose.yml` in your project root:

```yaml
version: "3.8"

services:
  web:
    build: .
    restart: always
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DATABASE_URL=postgresql://appuser:securepassword@db:5432/appdb
    depends_on:
      - db
    networks:
      - internal
      - proxy

  db:
    image: postgres:16-alpine
    restart: always
    environment:
      - POSTGRES_USER=appuser
      - POSTGRES_PASSWORD=securepassword
      - POSTGRES_DB=appdb
    volumes:
      - /var/data/postgres:/var/lib/postgresql/data
    networks:
      - internal

networks:
  internal:
  proxy:
    external: true # Shared Docker network for Caddy reverse proxy
```

### 2. Launching & Managing the Stack

```bash
# Create shared external network for Caddy reverse proxy
docker network create proxy

# Start stack in detached mode
docker compose up -d

# View running container logs
docker compose logs -f web

# Stop stack
docker compose down
```

## ⚙️ Alternative Branch 1: Bare-Metal Systemd Services

For applications running directly on the host OS (e.g., Node.js built via `fnm`), use Linux `systemd` user or system service units.

### 1. Create Systemd Service File

Create `/etc/systemd/system/myapp.service`:

```ini
[Unit]
Description=My Node.js Application Service
After=network.target postgresql.service

[Service]
Type=simple
User=toni
WorkingDirectory=/home/toni/my-app
ExecStart=/home/toni/.local/share/fnm/current/bin/node /home/toni/my-app/dist/server/entry.mjs
Restart=always
RestartSec=5

# Load environment variables
EnvironmentFile=/home/toni/my-app/.env

# Security Sandbox Options
ProtectSystem=full
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

### 2. Enable & Manage Service

```bash
# Reload systemd manager configuration
sudo systemctl daemon-reload

# Enable auto-start on boot and start service immediately
sudo systemctl enable --now myapp.service

# Check service status
sudo systemctl status myapp.service

# Tail service logs in real time
sudo journalctl -u myapp.service -f
```

## 🔀 Alternative Branch 2: Hybrid Deployment Model

In a hybrid architecture, application web servers run natively on the host OS via `systemd` (for maximum CPU/disk speed) while databases and caching layers run inside Docker containers.

### Connecting Host Systemd App to Dockerized Postgres

1. Ensure your Docker database maps container port `5432` to host port `5432`:

   ```bash
   -p 127.0.0.1:5432:5432
   ```

2. Point your native host application `.env` to `localhost`:

   ```ini
   DATABASE_URL="postgresql://appuser:securepassword@127.0.0.1:5432/appdb"
   ```

3. If a containerized app needs to reach a bare-metal host service, use `host.docker.internal`:
   ```yaml
   extra_hosts:
     - "host.docker.internal:host-gateway"
   ```
